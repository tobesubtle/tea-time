1. 시스템 개요 및 현재 운영 현황

1.1 시스템 개요

'Gemini 프롬프트 템플릿 매니저'는 생성형 AI(Google Gemini API) 활용 시 자주 사용되는 프롬프트 구조를 템플릿화하여 통합 관리하고, 동적 변수 입력 및 다중 소스 파일(로컬 PDF, Google Drive 파일) 첨부를 통해 고품질 프롬프트를 신속하게 생성·실행·관리할 수 있는 엔터프라이즈급 반응형 웹 서비스입니다.

📌 주요 기능 특징
  • 프롬프트 내 {{변수}} 템플릿 지정 및 모범 예시 매핑
  • 프롬프트 실행 내역 저장, 인라인 수정 및 Soft/Hard Delete
  • 백그라운드 메일 수신함 전송 및 429 쿼터 경고 알림 구축
  • Footer 기반 전역 PC/모바일 보기 모드 토글 지원
🌐 운영 현황
  • 배포 환경: Vercel Platform (자동 CI/CD 연동)
  • DB & 인증: Supabase (PostgreSQL, Auth, RLS)
  • 운영 상태: 정상 운용 중 (관리자 계정 통합 제어 및 API 쿼터 자동 모니터링 활성화)

2. 시스템 요구사항 및 세부 구현 내용

본 시스템은 사용자의 프롬프트 작성 편의성을 극대화하고 유연한 AI 모델 제어를 제공하기 위해 '프롬프트 관리 기능'과 '프롬프트 실행 기능'을 명확히 분리하여 구현하였습니다. 이를 통해 작성 단계에서는 템플릿 변수 입력과 자료 첨부에 집중하고, 실행 단계에서는 원클릭 AI 웹 바로가기, API 직접 호출 및 AI 모델 동적 변경을 자유롭게 수행할 수 있습니다.

2.1 프롬프트 관리 기능 (Prompt Management)

📋 템플릿 탐색 및 이력 관리
  • 카테고리 & 키워드 검색: 티타임, 보고서, 코드 등 카테고리 칩 필터링 및 SQL ILIKE 기반 실시간 검색어 조작
  • 템플릿 미리보기 & 제어: 선택된 템플릿 원본 내용 미리보기 및 템플릿 수정·복사·삭제 (TemplateActionHeader) 지원
  • 실행 이력 복구 및 삭제: 사용자별 실행 히스토리 최신순 조회, Soft Delete 및 관리자 대시보드 기반 Hard Delete / 복구 기능
✍️ 변수 대입 및 작성 화면 간소화
  • 동적 템플릿 변수 치환: {{변수}} 정규식 추출 및 사용자 입력값 동적 대입 (미입력 시 원본 유지)
  • 다중 소스 파일 첨부: 로컬 문서(PDF 등) 및 Google Drive API (GIS SDK Picker 연동) 파일 첨부 지원
  • 작성 UX 최적화: AI 모델 선택 옵션을 실행 단계로 이전하여 작성 단계의 복잡도를 낮추고 변수 입력에 집중하도록 단순화

3. 기술 스택 및 기술별 프로젝트 적용 사항

  • Next.js 16 (App Router): Server Components와 Server Actions를 적극 활용하여 초기 로딩 속도 최적화 및 클라이언트 번들 사이즈 최소화. next/og를 활용한 1200x630px 동적 SEO 오픈그래프 썸네일 카드 자동 생성.
  • TypeScript (Strict Mode): 프로젝트 전반에 strict: true 적용. any 타입을 엄격히 배제하고 Domain Interface와 Supabase DB 스키마 자동 추출 타입을 결합하여 100% 타입 안전성 확보.
  • Supabase (@supabase/ssr): Next.js App Router 서버-클라이언트 환경 간 쿠키/세션 동기화를 위해 최신 @supabase/ssr 패키지 적용. DB 단 RLS(Row Level Security) 정책을 완벽 적용하여 보안 이중 강화.
  • Nodemailer (SMTP): 프롬프트 결과 메일 발송 및 API 쿼터 초과 시 관리자 경고 메일 백그라운드 발송 Engine 구현.
  • Vanilla CSS / CSS Modules & Tailwind CSS v4: 글로벌 디자인 시스템(:root 토큰 변수)을 기반으로 CSS Modules와 Tailwind CSS v4를 혼용하여 고유하고 세련된 Dark/Light 디자인 구축.

4. 클린 아키텍처 (Clean Architecture) 및 설계 패턴 적용

본 프로젝트는 특정 기술(DB, 웹 프레임워크, 외부 AI API)의 변화에 시스템 핵심 규칙이 흔들리지 않도록 계층형 클린 아키텍처(Clean Architecture) 원칙을 엄격히 적용하였습니다.

4.1 클린 아키텍처의 일반적 특징 및 핵심 장점

🧩 관심사의 분리 (Separation of Concerns)

핵심 비즈니스 규칙(Domain)을 UI, 데이터베이스, 외부 API 등 기술적 세부사항(Infrastructure)과 격리하여 독립적인 계층으로 구성합니다.

🔄 의존성 역전 원칙 (Dependency Inversion Principle)

의존성의 방향은 항상 외곽(UI/DB)에서 중심(Domain)으로만 향합니다. 도메인은 구현체가 아닌 추상화된 인터페이스에만 의존합니다.

🧪 독립적인 테스트 가능성 (Testability)

데이터베이스, 웹 서버, 외부 AI 서비스 없이도 순수한 도메인 엔티티와 비즈니스 유스케이스를 100% 독립된 단위 테스트(Unit Test)로 검증할 수 있습니다.

⚡ 프레임워크 및 외부 서비스의 독립성

데이터베이스(Supabase → PostgreSQL Direct/Prisma)나 외부 서비스(Gemini → Claude/OpenAI) 변경 시 도메인 코드의 수정 없이 유연하게 확장 가능합니다.

4.2 본 프로젝트의 계층 구조 및 실제 적용 사례

src/
├── domain/                 # [Domain Layer] 외부 기술에 독립적인 순수 비즈니스 로직
│   ├── entities/           # 비즈니스 데이터 모델 (User, PromptTemplate, PromptHistory, QuotaLog 등)
│   ├── repositories/       # 저장소 추상 인터페이스 (TemplateRepository, PromptHistoryRepository 등)
│   └── usecases/           # 비즈니스 유스케이스 오케스트레이션 (ExecutePromptUseCase 등)
├── infrastructure/         # [Infrastructure Layer] 외부 시스템 및 기술 구현체
│   ├── api/                # Gemini API (geminiClient) 및 Google Drive API 래퍼
│   ├── db/                 # Supabase Client 설정 및 DB 연결
│   └── repositories/       # domain/repositories 추상 인터페이스의 실제 구현체 (Supabase...Repository)
├── presentation/           # [Presentation Layer] UI 및 화면 제어 계층
│   ├── components/         # React UI 컴포넌트 (PromptRunActions, ModelSelectAccordion 등)
│   ├── hooks/              # 커스텀 React 훅
│   └── store/              # Zustand 클라이언트 상태 관리
└── shared/                 # 공통 유틸리티, 상수, 에러 타입
app/                        # [Framework Layer] Next.js App Router 진입점 (Routing 및 Page 조합)
💡 본 프로젝트에서의 클린 아키텍처 핵심 적용 성과
  • DB 및 인프라 교체 용이성: PromptHistoryRepository 인터페이스를 Domain 계층에 정의하고, Infrastructure 계층에서 SupabasePromptHistoryRepository로 구현(implements)했습니다. 이를 통해 추후 Supabase에서 다른 DB나 ORM(Prisma, Drizzle 등)으로 전환하더라도 비즈니스 로직 수정 없이 구현체만 교체하면 됩니다.
  • Multi-LLM 확장성 확보: 현재 Gemini API(geminiClient)를 사용하고 있으나, Claude나 OpenAI 등 타 모델을 추가하더라도 Domain 인터페이스 규약만 준수하도록 Infrastructure에 클라이언트를 추가하면Presentation 계층의 변경을 최소화하며 유연하게 Multi-LLM으로 확장할 수 있습니다.
  • 프레임워크 독립성: Next.js 16 App Router의 라우팅 역할을 app/ 폴더로 한정하고, 실제 UI와 상태 관리는 src/presentation/에 둠으로써 프레임워크 버전 업그레이드나 패키지 변경 시 핵심 서비스 영향도를 최소화했습니다.

5. Antigravity와의 AI Pair Programming 협업 내용 및 노하우

5.1 AI 협업 방식 및 개발 워크플로우

  • 규칙 기반 가이드라인 통제 (.agents/rules/): tech-stack.md, architecture.md, AGENTS.md 등을 명시하여 AI가 생성하는 모든 코드가 클린 아키텍처 규칙 및 TypeScript Strict 규칙을 일탈하지 않도록 엄격 제어.
  • TDD (Red-Green-Refactor) 기반 개발: 단위/통합 테스트 케이스를 우선 작성(system_test_cases.md)하고, Antigravity 에이전트가 이를 통과하는 코드를 작성 및 리팩토링하도록 유도.
  • 서브에이전트(Subagents) 및 특화 스킬(Skills) 활용: 코드베이스 탐색, PRD 검증, 리팩토링 및 린트 검사를 병렬로 처리하여 순수 개발 시간 약 60% 단축.

5.2 AI 활용 생산성 성과

Strict 타입 안전성 100% 확보, 린트 에러 0건 유지, 요구사항 변경 시 테스트 케이스와 코드 간 자동 동기화로 품질 혁신 달성.

6. 주요 트러블슈팅 및 레슨 러닝 (Lessons Learned)

🔴 Supabase SSR 세션 동기화 이슈

문제: Server Component와 Client Component 간 쿠키 세션 전달 시 인증 상태 불일치 발생.

해결: 최신 @supabase/ssr 기반의 createBrowserClient 및 createServerClient를 분리 적용하고 middleware에서 세션 자동 갱신 처리.

🔴 Gemini API 쿼터 제한(429 Error) 대응

문제: 대용량 프롬프트 처리 시 429 Resource Exhausted 에러 발생으로 서비스 지연 위험.

해결: 429 감지 시 quota_error_logs DB 테이블 기록 및 Nodemailer 백그라운드 경고 메일을 관리자에게 즉시 발송하는 모니터링 구축.
